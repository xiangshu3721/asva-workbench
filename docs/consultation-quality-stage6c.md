# ASVA Stage 6C — 咨询视角质量评估协议（V1，离线）

> 目标：在不接触真实客户隐私的前提下，让质量评估可重复、可归因，不用“感觉不错”代替证据。

## 1. 测试范围与不能证明的事

自动 Golden Set：`src/consultation-quality-golden.test.ts`，使用 **21 个虚构客户场景 + 3 个跨客户/确定性合约断言**。从 `buildConsultationInputSnapshot` → `buildConsultationTopics` → `buildConsultationPanelView` 全程验证**实际 H5 所展示**的主题和开场建议。

自动检查：有明确诉求时对应议题、只有方向时保持初步方向、目标/背景不伪装为困扰、已解决历史/否认/第三方观察/AI 推断不升级、未决冲突不强行择边、跨客户证据不串用、来源 ID 可追溯、开场不预设心理原因、长文本不重复全文、重复输入结果稳定。

**这套自动测试不能证明**：DeepSeek 生成的深层分析一定真实、导师说出口自然、客户接受度高、咨询实际有效。它不会联网、调用 DeepSeek、更新飞书或操作生产客户。

## 2. 导师盲评表（2 人交叉评估）

选择 6–10 个**合成模拟客户**进行首轮人工评审（如能获得合法授权、完整去标识化且经隐私审核的真实案例，可在隔离环境中另做第二轮，**不得上传到 GitHub**）。

每个案例提供：简短的资料摘要、来源与确认状态、当前核心议题、系统展示的咨询切入点、导师对回答的评估。不要给评审者模型版本、开发者提示或预期答案；两名导师独立评分后再讨论分歧。

| 维度 | 1 分（不合格） | 3 分（需改进） | 5 分（优良） |
|---|---|---|---|
| **资料忠实度** | 编造背景、把推测当事实 | 大体贴合但遗漏重要限制 | 与已知资料一致，不确定性清楚 |
| **议题相关性** | 偏离客户实际诉求 | 相关但过于笼统 | 直接对应当前已记录需求 |
| **会谈可执行性** | 导师不能直接采用 | 可用但需大量改写 | 可以自然开口，并能进入具体情境 |
| **自然与尊重** | 机械、预设、审问式 | 偶有模板感 | 开放、简洁、包容，不替客户下定义 |
| **证据及安全边界** | 越权诊断、泄露资料、虚构确认 | 有边界但提醒不充分 | 来源与事实/推断区分准确 |

每维评分 **1–5 分**；另记：`严重错误 Y/N`、案例描述、问题位置、可执行改法，保留评审者独立意见和分歧。**不要把模型自报 confidence 当作评审分数。**

## 3. 严重错误一票否决

出现以下任何一项，本轮不得宣布质量验收完成：跨客户资料/证据泄漏；从身份背景臆断困扰；把未确认 AI/第三方推断当事实；未经依据的心理诊断或定性；忽略明确否认或已解决历史；引用了错误客户来源；对个体直接下危险或冒犯性结论。

## 4. 阶段性通过门槛（预先设定，不等于实际已通过）

1. 自动 Golden Set 全部 PASS，项目全量回归、TypeScript、构建 PASS。
2. 人工盲评至少 **6 个不同场景**，两名导师均评分；**严重错误数 0**。
3. 各维度所有评分的平均值达到 **4/5**，且没有任何案例在“资料忠实度”或“证据及安全边界”上得到 1 分；低分案例必须逐一复盘。
4. 将自动覆盖与人工评审**分开报告**：样本数、差错数、平均分、评分分歧、未覆盖风险和复测计划。

无法获得两位导师或足够案例时，回报 `AUTO_PASS / HUMAN_REVIEW_PENDING`，**不能声称 6C 全面通过**。

## 5. 本轮交付边界

- 本 PR 除离线测试与评估协议外，还修复了 `shared/consultation-topics.mjs` 中句级否定/已解决的误判：仅在能辨认独立当前议题且与历史/已解决议题属不同领域时保留，否则保守排除。**这是线上共享业务逻辑改动，验收通过后需要独立核实前端 Pages 与 CloudBase API 发布范围，不能冒充测试专用变更。**
- 不使用真实客户姓名、电话、微信、原始录音、可识别具体经历或隐私材料。
- 真正的模型生成质量需要经批准的脱敏案例离线对照；工作流不得为凑样本自动对生产客户调用模型。
- 自动测试如果失败，先保留失败证据（仅合成数据），单独提出最小修复，不临时放宽评估标准来“刷 PASS”。
