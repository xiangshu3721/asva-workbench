## 二、架构设计

### 2.1 数据流

```
导师导入测评 → asva_assessment_bindings (ACTIVE)
  ↓
repository.getCustomerUnderstanding()
  ↓ (并行)
  ├── this.load() → 客户档案 + evidence + sources
  └── assessmentStore.getCustomerAssessments() → bindings
  ↓
extractAllAssessmentSummaries() → 测评摘要
  ↓
buildCustomerUnderstandingContext({ ..., assessmentSummaries })
  ↓
assessment_summaries 加入上下文
  ↓
understandingInputFingerprint() → 包含测评哈希
  ↓
STALE检测 → 测评变化触发刷新
  ↓
createCustomerUnderstanding() → DeepSeek (含测评指令)
  ↓
返回结构化理解
```

### 2.2 测评摘要结构

```javascript
{
  available: true,
  count: 2,
  summaries: [{
    assessment_id: 'star',
    assessment_name: '职业六芒星',
    completed_at: '2026-11-27T10:00:00+08:00',
    headline: '底层动力: 创造性、自由',
    summary: '现实追求: 安全、新鲜感',
    caution: '',
    key_metrics: [{ name: '底层动力', labels: ['创造性', '自由'] }],
    assessment_evidence_ref: 'ASM-TEST01',
  }],
  note: '以上是...客户自评的结构化整理，不是临床诊断...'
}
```

### 2.3 安全边界

- **不发送原始答题数据**: 只发送 preview 中的摘要和指标
- **不发送凭证**: 无 linkSecret, ownerToken, encryptedShareUrl
- **文本截断**: headline 200字符, summary 400字符, labels 80字符
- **指标限制**: 最多4个指标,每个最多5个标签
- **读取失败不阻塞**: catch 错误,返回空数组

## 六、更新机制

### 6.1 测评更新

1. 导师粘贴新链接 → 更新报告
2. 新绑定创建,snapshotHash 变化
3. assessmentFingerprint 变化
4. understandingInputFingerprint 变化
5. STALE 检测触发
6. 下次刷新使用最新测评数据

### 6.2 解绑

1. 导师点击解绑 → 状态变为 UNBOUND
2. getCustomerAssessments 不再返回该绑定
3. extractAllAssessmentSummaries 跳过
4. assessmentFingerprint 变化
5. STALE 检测触发
6. 下次刷新不再包含该测评

### 6.3 撤销

1. 导师撤销 → sourceRevoked/localRevoked = true
2. isEligibleForUnderstanding 返回 false
3. 测评不参与分析
4. 指纹变化 → STALE → 刷新
