## 变更概要

### 1. 修复「查看原报告」跳转 — 三处关键修正
**问题 1**: 原实现使用 `window.open(url, '_blank', 'noopener,noreferrer')`，`noopener` 导致返回的窗口引用为 null，无法后续导航。

**问题 2**: 服务端 302 重定向无法携带 Authorization Bearer Token（浏览器直接打开链接不附带请求头），导致鉴权失败。

**修正**: 移除服务端 302 端点，复用已鉴权的 `share-url` API：
1. 打开空白标签页 `window.open('about:blank', '_blank')`（不使用 `noopener`，保留窗口引用）
2. 调用 `api.getAssessmentShareUrl()` 获取链接（Authorization 通过 Bearer Token 传递）
3. 导航已打开的标签页 `newTab.location.href = result.shareUrl`
4. 安全断开 `newTab.opener = null`
5. 失败时关闭空白页或提示补充链接
6. **不将 Token 放入 URL，不降低权限校验**

### 2. 数据读取 — 补齐列表 RPC 缺失字段
**问题**: PostgreSQL 列表 RPC (`get` action with customerId) 未返回 `snapshot` 和 `hasEncryptedShareUrl`，导致：
- 服务端快照补齐无法工作（没有 snapshot 数据）
- 前端按钮判断失效（`hasEncryptedShareUrl` 始终为 false）

**修正**: 新增 SQL 迁移 `20261128100000_v13_fix_list_snapshot_and_share_url.sql`：
- 列表查询返回 `snapshot`（仅服务端使用）
- 列表查询返回 `hasEncryptedShareUrl`（布尔标志，用于前端按钮逻辑）
- Node.js 层在返回列表时自动从快照重新生成 `displayPayload`
- **不将完整快照返回给前端**，不逐条发起网络查询，不要求导师重新录入

### 3. 测评卡片增强可视化 — 复用原版视觉结构
新增 `AssessmentCardVisualization` 组件，直接读取 mindtest-web 对应结果页的实际渲染结构和 CSS 变量：

| 测评类型 | 原版结构 | 卡片实现 |
|---------|---------|---------|
| 职业六芒星 (star) | SVG 双三角形六芒星 + drive/pursue 词表 | 相同 SVG 结构 + 宋体标题 + 虚线分隔词列表 |
| Beattie 情绪系列 | `result-score` + `bar-track` 圆角进度条 | 宋体大字等级 + 圆角进度条 + 子维度分项 |
| 主观体验地图 (sefs) | SVG 雷达图 + 固定评分范围 | SVG 雷达图，固定 30 分/维度，保持原版维度顺序 |

**关键原则**:
- 不使用当前最高分作为归一化上限，使用固定评分范围（30 分/维度）
- 保持原版维度顺序
- 不编造指标，不将缺失值当作零分或正常结果
- CSS 使用 mindtest-web 原版色彩变量（`#7a3140` 六芒星、`#6e4028` Beattie 深棕、`#4caf50` SEFS 绿色）

### 4. SEFS 主观体验地图数据修复
**问题**: SEFS 适配器原读取路径为 `report.score || report.viewModel`，但实际 H5 报告存储在 `report.reportContent.viewModel`，导致总分为空、最高维度显示"未确定"。

**修复**: 适配器优先读取 `report.reportContent?.viewModel`，兼容旧 `score`/`viewModel` 路径。同时支持 `dimensions` 和 `items` 两种数组格式。

### 5. H5 分享能力判断修正
将 SEFS（主观体验地图）加入 H5 分享能力列表（共 8 种），因其实际存在可导入的 H5 报告页面。

### 6. 按钮逻辑细化
- H5 能力 && 已存链接 → 显示「查看原报告」
- H5 能力 && 未存链接 → 显示「补充原报告链接」
- 非 H5 能力测评 → 不显示以上按钮
- 保留「更新记录」和「解绑」按钮不变
